# فیت‌بات — نسخه PHP ۳.۰

داشبورد فارسی و راست‌به‌چپ تمرین، تغذیه و پیشرفت، با بک‌اند واقعی **PHP 8.2+ و SQLite**.
رابط کاربری با HTML/CSS/JavaScript ساده اجرا می‌شود؛ PHP مسئول حساب‌ها، ذخیره‌سازی، API برنامه‌ساز و محاسبه‌گر، و اتصال سروری ایجنت‌هاست. این نسخه تغییر پسوند HTML نیست.

**اجرای پروژه به Node.js، npm، Composer، CDN یا MySQL نیاز ندارد.**

## اجرای سریع

۱. پوشه ZIP را استخراج کن و وارد `fitbot-php` شو.
۲. PHP 8.2 یا جدیدتر با افزونه‌های `pdo_sqlite` و `mbstring` لازم است. `curl` فقط برای اتصال مدل زبانی لازم است.
۳. از ریشه پروژه اجرا کن:

```bash
php -S 0.0.0.0:8080 -t public router.php
```

سپس در مرورگر همان دستگاه باز کن:

```text
http://localhost:8080
```

دیتابیس `storage/fitbot.sqlite` و جدول‌ها خودکار ساخته می‌شوند؛ import کردن SQL لازم نیست. پوشه `storage` باید برای کاربری که PHP را اجرا می‌کند قابل نوشتن باشد. دسترسی عمومی `777` نده.

> فایل PHP با دوبارکلیک اجرا نمی‌شود و پیش‌نمایش متنی فایل PHP هم وب‌سرور نیست. پروژه را با دستور بالا یا وب‌سرور PHP اجرا کن.

### XAMPP / Laragon

- از نسخه‌ای با PHP 8.2+ استفاده کن.
- افزونه‌های `pdo_sqlite`، `sqlite3`، `mbstring` و در صورت نیاز `curl` را در `php.ini` فعال کن و Apache را راه‌اندازی مجدد کن.
- روش ساده محلی: پوشه پروژه داخل `htdocs` قرار بگیرد؛ نشانی `http://localhost/fitbot-php/public/` را باز کن.
- روش توصیه‌شده، به‌خصوص برای انتشار: DocumentRoot هاست یا VirtualHost را **مستقیماً روی `fitbot-php/public`** تنظیم کن.
- `.htaccess` ریشه و پوشه public برای جلوگیری از فهرست‌شدن پوشه‌ها و دسترسی مستقیم به فایل‌های خصوصی قرار داده شده است؛ این جایگزین تنظیم صحیح DocumentRoot نیست.

## امکانات اجراشده

- داشبورد واکنش‌گرا، تم روشن/تاریک، فونت فارسی محلی و ناوبری موبایل.
- ورود، ثبت‌نام، خروج و حذف حساب با تأیید رمز.
- اطلاعات جداگانه هر حساب در SQLite؛ رمزها با `password_hash` ذخیره می‌شوند.
- حالت مهمان مستقل از حساب: داده مهمان در مرورگر باقی می‌ماند و فقط با انتخاب صریح هنگام ثبت‌نام به حساب جدید منتقل می‌شود.
- ذخیره خودکار داده حساب با نشانگر وضعیت؛ داده‌های حساب در localStorage مهمان نوشته نمی‌شوند.
- کنترل تداخل نسخه‌ها: تغییرات قدیمی، داده دستگاه یا تب دیگر را بی‌خبر جایگزین نمی‌کنند؛ انتخاب نسخه از پنجره حساب انجام می‌شود.
- برنامه‌ساز سه‌مرحله‌ای با ۲ تا ۵ روز تمرین، سطح تجربه، زمان و تجهیزات. مرحله مرور برنامه از API واقعی PHP نتیجه می‌گیرد.
- محاسبه‌گر BMR، TDEE و ماکرو با فرمول Mifflin–St Jeor و اعتبارسنجی سمت سرور. پیش‌نمایش‌های فوری رابط نیز منطق متناظر دارند؛ محاسبه‌گر و مرور نهایی برنامه از PHP استفاده می‌کنند.
- کتابخانه ۲۴ حرکت با جستجو، فیلتر، علاقه‌مندی، راهنمای متنی و انیمیشن نمادین قابل توقف.
- جلسه تمرین، ثبت تکمیل حرکات و تایمر استراحت با مکث/ادامه.
- ثبت وزن، نمودار واقعی، تقویم جلسه‌های تکمیل‌شده، ثبت آب و وعده‌های غذایی.
- سهم‌های غذایی تخمینی و پیشنهاد گیاهی؛ مواد و ماکروهای وعده ثبت‌شده با تغییر هدف دوباره‌نویسی نمی‌شوند.
- هماهنگ‌کننده و سه نقش تمرین، تغذیه و ریکاوری؛ راهنمای قانون‌محور داخلی و اتصال اختیاری به مدل زبانی.
- پیشنهاد اقدام در گفتگو؛ ثبت آب و تغییر هدف فقط پس از کلیک تأیید اجرا می‌شوند.
- خروجی برنامه TXT، اندازه‌گیری CSV، پشتیبان JSON و بازیابی پشتیبان.
- فرمان‌های سریع با `Ctrl+K` یا `Cmd+K`، کنترل صفحه‌کلید و پشتیبانی `prefers-reduced-motion`.
- انیمیشن ذرات محدود به ناحیه قابل مشاهده، پارالاکس ملایم، مدار ایجنت‌ها، رسم نمودار، گذار پنجره‌ها و بازخورد تکمیل تمرین.

## اتصال واقعی مدل زبانی

بدون کلید، همه امکانات پایه و راهنمای قانون‌محور داخلی کار می‌کنند. **این راهنمای داخلی یک مدل زبانی نیست.**

۱. فایل `.env.example` را در ریشه پروژه به `.env` کپی کن:

```bash
cp .env.example .env
```

در ویندوز می‌توانی فایل را دستی کپی و تغییرنام بدهی.

۲. فقط در فایل سرور تنظیم کن:

```dotenv
OPENAI_API_KEY=your_server_side_key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1
AI_USER_DAILY_LIMIT=30
AI_GLOBAL_DAILY_LIMIT=100
```

مدل باید از **Chat Completions و tool calling** پشتیبانی کند. نشانی سرویس دیگرِ سازگار را هم می‌توان در `OPENAI_BASE_URL` تنظیم کرد. URL و کلید از مرورگر گرفته نمی‌شوند. اگر مدل از پارامترهای `max_tokens` یا `temperature` پشتیبانی نمی‌کند، payload را در `app/AgentService.php` متناسب با مستندات همان سرویس تغییر بده.

۳. وارد حساب شو. در «تیم ایجنت‌ها ← اتصال هوش مصنوعی»، رضایت ارسال پیام و مشخصات پایه را تأیید و حالت مدل را فعال کن.

- کلید واقعی داخل HTML، JavaScript، پاسخ API یا فایل ZIP نیست.
- درخواست از `public/api.php?action=agent` به `app/AgentService.php` می‌رود و با cURL به سرویس مدل ارسال می‌شود.
- مدل فقط پیشنهاد اقدام برمی‌گرداند؛ نوشتن خودکار در سوابق سلامت مجاز نیست.
- حالت مدل پس از تازه‌سازی صفحه دوباره نیاز به فعال‌سازی دارد.
- هزینه و سیاست نگهداری داده به سرویس انتخابی بستگی دارد. محدودیت داخلی، سقف تعداد درخواست است، نه تضمین سقف هزینه؛ روی حساب ارائه‌دهنده هم محدودیت بودجه قرار بده.
- مسیر cURL و قرارداد tool calling با سرویس آزمایشی محلی تست شده‌اند. کلید سرویس واقعی در این پروژه تنظیم نشده و اتصال زنده با حساب واقعی تست نشده است.

## ذخیره و حریم خصوصی

### مهمان

کلید `fitbot.php.guest.v1` در localStorage فقط اطلاعات مهمان را نگه می‌دارد. اگر مرورگر یا iframe ذخیره‌سازی را محدود کند، نشانگر حالت موقت نمایش داده می‌شود. مشخصات واردشده برای محاسبه نهایی به PHP همین برنامه فرستاده می‌شوند، اما بدون حساب در جدول سوابق کاربران ثبت نمی‌شوند.

### حساب

سوابق و گفتگوها روی سرور همین برنامه ذخیره می‌شوند. نشانگر بالای صفحه وضعیت «ذخیره‌شده»، «در انتظار»، «خطا» یا «تداخل نسخه» را مشخص می‌کند. پیش از خروج یا بستن صفحه، ذخیره‌شدن را بررسی کن. خطای شبکه یا تداخل، به‌عنوان ذخیره موفق نمایش داده نمی‌شود. در قطع اتصال، اطلاعات جدید در حافظه همان صفحه می‌مانند؛ پشتیبان بگیر.

- خروج، داده حساب را از رابط و سند جاری پاک می‌کند و داده مستقل مهمان را دوباره بارگیری می‌کند.
- «پاک‌کردن داده‌های ورزشی» حساب را نگه می‌دارد ولی برنامه و سوابق آن را پاک می‌کند.
- «حذف حساب» در پنجره حساب، با تأیید رمز، رکورد کاربر و سوابق وابسته را حذف می‌کند.
- پشتیبان‌های دانلودشده یا پشتیبان سرور جداگانه‌اند و خودکار از دستگاه‌های دیگر پاک نمی‌شوند.
- پایگاه داده SQLite به‌صورت پیش‌فرض رمزنگاری در حالت سکون ندارد. فایل‌ها، پوشه storage و نسخه‌های پشتیبان باید در دسترس عمومی نباشند. برای اطلاعات حساس و انتشار واقعی، مدیریت دسترسی، رمزنگاری مناسب، سیاست نگهداری داده و ممیزی لازم است.
- ظرفیت نگهداری فعلی: حداکثر ۱۰۰۰ ثبت وزن، ۱۰۰۰ جلسه، ۳۶۵ روز داده آب/غذا، ۴۰ پیام برای هر نقش و ۴۰ رویداد. حجم snapshot محدود است؛ خروجی‌های دوره‌ای نگه دار.

## دیتابیس و ساختار

```text
fitbot-php/
├── public/
│   ├── index.php              # ساخت سند و داده اولیه مجاز همان حساب
│   ├── api.php                # API با session و CSRF
│   └── assets/                # CSS، JavaScript، عکس و فونت محلی
├── app/
│   ├── bootstrap.php         # راه‌اندازی و autoload بدون Composer
│   ├── Config.php            # متغیر محیطی و .env
│   ├── Auth.php              # حساب، نشست، هش رمز
│   ├── Database.php          # PDO، schema، نسخه داده و محدودیت درخواست
│   ├── StateValidator.php    # اعتبارسنجی و حذف فیلدهای ناشناخته
│   ├── FitnessService.php    # محاسبه انرژی و تولید برنامه در PHP
│   ├── AgentService.php      # مدل زبانی و پیشنهاد ابزار با cURL
│   ├── Http.php              # پاسخ، ورودی JSON و CSRF
│   ├── ApiException.php
│   └── data/                 # کاتالوگ حرکت، نقش‌ها و داده‌های نمونه
├── templates/layout.php      # قالب فارسی و RTL
├── storage/                  # خصوصی؛ دیتابیس و فایل‌های session
├── tests/run.php             # آزمون‌های مستقل PHP
├── router.php                # فقط برای سرور توسعه PHP
├── .env.example
├── API.md
└── README.fa.md
```

جدول‌ها:

- `users`: نام، ایمیل، هش رمز و زمان ایجاد.
- `user_states`: یک snapshot JSON اعتبارسنجی‌شده برای هر کاربر، همراه شماره نسخه و زمان ذخیره. این نسخه برای سادگی انتقال و backup، به‌جای جدول مجزا برای هر نوع حرکت/وعده از snapshot استفاده می‌کند.
- `rate_limits`: شمارنده محدودیت درخواست؛ کلیدها هش شده‌اند.

JSON پشتیبان هنوز `version: 2` دارد تا با ساختار داده نسخه قبلی سازگار باشد؛ نسخه نرم‌افزار PHP برابر ۳.۰ است.

## اجرای تست

از ریشه پروژه:

```bash
php tests/run.php
```

تست، دیتابیس موقت مستقل می‌سازد و پس از پایان پاک می‌کند؛ دیتابیس واقعی پروژه را تغییر نمی‌دهد. ۲۸۸ ترکیب پارامتر برنامه‌ساز، فرمول‌ها، اعتبارسنجی، round-trip دیتابیس، رد نسخه قدیمی، محدودیت ابزارهای مدل و حذف وابسته داده را پوشش می‌دهد. اجرای برنامه و همین تست به Node نیاز ندارد.

علاوه بر تست همراه، در زمان ساخت ۶۸ بررسی مرورگری/HTTP و ۱۳ بررسی اتصال مدل با mock اجرا شده‌اند؛ جزئیات در `TEST_REPORT.fa.md` است.

## انتشار و محدودیت‌های نسخه

- سرور `php -S` فقط برای توسعه است. برای انتشار از PHP-FPM/Apache و HTTPS استفاده کن.
- فقط `public/` در معرض وب باشد؛ `.env`، دیتابیس، session و گزارش‌ها هرگز داخل پوشه عمومی قرار نگیرند.
- `APP_ENV=production` را تنظیم کن. عملیات ورود/ثبت‌نام در این حالت بدون شناسایی HTTPS رد می‌شود.
- پشت پروکسی مورد اعتماد، `TRUST_PROXY=true` قرار بده. این گزینه را وقتی سرور از اینترنت مستقیم و بدون پروکسی قابل دسترسی است، کورکورانه فعال نکن.
- در حالت trusted proxy، هدر `X-Forwarded-Host` هم بررسی می‌شود. اگر مبدأ هنوز با تنظیم پروکسی هماهنگ نیست، `APP_ORIGIN` را برابر مبدأ دقیق قابل مشاهده برای مرورگر، بدون اسلش انتهایی تنظیم کن.
- نشست‌ها پس از دو ساعت عدم فعالیت حساب منقضی می‌شوند؛ کوکی HttpOnly و در HTTPS به‌صورت Secure است.
- برای iframe روی HTTPS می‌توان از `SESSION_SAMESITE=None` و `SESSION_PARTITIONED=true` استفاده کرد (مرورگرهای دارای CHIPS). اگر کوکی همچنان محدود است، از تب مستقل استفاده کن. پیش‌فرض معمول، `Lax` است.
- CSRF، SQL پارامتری، CSP با nonce، محدودیت اندازه درخواست و rate limit اضافه شده‌اند؛ این‌ها به معنای «امنیت تضمین‌شده» یا آماده‌بودن برای هر محیط تولید نیستند.
- در این نسخه ایمیل تأیید نمی‌شود، بازیابی رمز با ایمیل و MFA وجود ندارد. پیش از انتشار عمومی، این امکانات، پایش و پشتیبان‌گیری مدیریتی را اضافه کن.
- برای پشت پروکسی بزرگ، rate limit پیش‌فرض از IP اتصال استفاده می‌کند، نه X-Forwarded-For دلخواه کاربر؛ ممکن است چند کاربر محدودیت مشترک داشته باشند. تنظیم trusted proxy را متناسب با زیرساخت بررسی کن.

## نکته سلامت و رسانه

محاسبه‌ها و وعده‌ها **تخمینی و عمومی** هستند. برنامه برای بزرگسالان است؛ جایگزین ارزیابی پزشکی، رژیم درمانی یا مربی واجد صلاحیت نیست. برای بارداری، بیماری، آسیب یا درد، ارزیابی تخصصی لازم است. انیمیشن حرکت‌ها نمادین‌اند و فرم دقیق بدن را آموزش نمی‌دهند.
