# فیت‌بات — نسخه PHP ۳.۰

داشبورد فارسی و راست‌به‌چپ تمرین، تغذیه و پیشرفت، با بک‌اند واقعی **PHP 8.2+** و دیتابیس **MySQL یا SQLite**.
رابط کاربری با HTML/CSS/JavaScript ساده اجرا می‌شود؛ PHP مسئول حساب‌ها، ذخیره‌سازی، API برنامه‌ساز و محاسبه‌گر، و اتصال سروری ایجنت‌هاست. این نسخه تغییر پسوند HTML نیست.

**اجرای پروژه به Node.js، npm، Composer یا CDN نیاز ندارد؛** MySQL اختیاری است — پیش‌فرض SQLite است ولی با فایل `database/fitbot_mysql.sql` و چند خط تنظیم در `.env`، برنامه کاملاً روی MySQL اجرا می‌شود.

## اجرای سریع

۱. پوشه ZIP را استخراج کن و وارد `fitbot-php` شو.
۲. PHP 8.2 یا جدیدتر با افزونه‌های `mbstring` و `pdo_sqlite` (یا برای MySQL: `pdo_mysql`) لازم است. `curl` فقط برای اتصال مدل زبانی لازم است.
۳. از ریشه پروژه اجرا کن:

```bash
php -S 0.0.0.0:8080 -t public router.php
```

سپس در مرورگر همان دستگاه باز کن:

```text
http://localhost:8080
```

دیتابیس `storage/fitbot.sqlite` و جدول‌ها خودکار ساخته می‌شوند؛ import کردن SQL لازم نیست. پوشه `storage` باید برای کاربری که PHP را اجرا می‌کند قابل نوشتن باشد. دسترسی عمومی `777` نده.

> فایل PHP با دوبارکلیک اجرا نمی‌شود و پیش‌نمایش متنی فایل PHP هم وب‌سرور نیست. پروژه را با دستور بالا یا وب‌سرور PHP اجرا کن.

### XAMPP / Laragon

- از نسخه‌ای با PHP 8.2+ استفاده کن.
- افزونه‌های `mbstring`، `pdo_sqlite` (و برای MySQL: `pdo_mysql`) و در صورت نیاز `curl` را در `php.ini` فعال کن و Apache را راه‌اندازی مجدد کن.
- روش ساده محلی: پوشه پروژه داخل `htdocs` قرار بگیرد؛ نشانی `http://localhost/fitbot-php/public/` را باز کن.
- روش توصیه‌شده، به‌خصوص برای انتشار: DocumentRoot هاست یا VirtualHost را **مستقیماً روی `fitbot-php/public`** تنظیم کن.
- `.htaccess` ریشه و پوشه public برای جلوگیری از فهرست‌شدن پوشه‌ها و دسترسی مستقیم به فایل‌های خصوصی قرار داده شده است؛ این جایگزین تنظیم صحیح DocumentRoot نیست.

## دیتابیس MySQL

برای اجرای برنامه روی **MySQL/MariaDB** (مثلاً با phpMyAdmin):

۱. فایل `database/fitbot_mysql.sql` را ایمپورت کن:

- **phpMyAdmin:** یک دیتابیس بساز (مثلاً `fitbot`) → تب **Import** → انتخاب همین فایل → **Go**.
- **خط فرمان:** `mysql -u root -p < database/fitbot_mysql.sql`

فایل شامل ۵ جدول `users`، `user_states`، `rate_limits`، `admins` و `admin_activity` با کلید خارجی، ایندکس و یک حساب مدیر پیش‌فرض است.

۲. فایل `.env.example` را به `.env` کپی کن و بخش دیتابیس را پر کن:

```dotenv
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=fitbot
DB_USER=root
DB_PASS=
```

- در XAMPP/Laragon معمولاً user برابر `root` با رمز خالی است.
- پیشنهاد امنیتی: به‌جای root، یک کاربر اختصاصی بساز: `CREATE USER 'fitbot'@'localhost' IDENTIFIED BY 'رمز'; GRANT ALL PRIVILEGES ON fitbot.* TO 'fitbot'@'localhost';` و همان را در `.env` وارد کن.
- افزونه `pdo_mysql` باید در `php.ini` فعال باشد (در XAMPP و Laragon فعال است).
- اگر جداول را ایمپورت نکنی، برنامه در اولین اجرا خودش می‌سازد (به مجوز CREATE نیاز دارد)؛ ایمپورت فایل SQL روش تمیزتر است.
- با `DB_DRIVER=sqlite` (پیش‌فرض) همه‌چیز مثل قبل بدون ایمپورت و با `storage/fitbot.sqlite` کار می‌کند؛ **هر دو حالت از یک کد و یک API پشتیبانی می‌شوند.**

## پنل مدیریت (ادمین)

نشانی: `public/admin/` — مثلاً `http://localhost:8080/admin/` یا در XAMPP: `http://localhost/fitbot-php/public/admin/`

- حساب پیش‌فرض: نام کاربری **`admin`** و رمز **`Admin@12345`** — **بلافاصله بعد از اولین ورود، از صفحه «پروفایل من» رمز را عوض کن.** تا وقتی رمز عوض نشده، پنل هشدار زرد نشان می‌دهد.
- **داشبورد:** آمار کاربران (کل/فعال/مسدود/ثبت‌نام هفته)، کاربران دارای داده، تعداد مدیران، اقدام‌های اخیر و آخرین ورودها.
- **کاربران:** جستجو بر اساس نام/ایمیل، صفحه‌بندی، مشاهده پروفایل هر کاربر (مشخصات بدنی، تعداد وزن‌ها، جلسات، پیام‌ها و…، همه فقط-خواندنی)، **مسدودسازی/فعال‌سازی** (کاربر مسدود نمی‌تواند وارد شود و نشست فعالش باطل می‌شود) و **حذف کامل** با تأیید.
- **مدیران (فقط مدیر کل):** ساخت مدیر جدید با رمز دلخواه، تعیین سطح دسترسی (مدیر کل / مدیر عادی) و حذف مدیر. مدیر عادی به داشبورد، کاربران و گزارش‌ها دسترسی دارد ولی نمی‌تواند مدیر بسازد یا حذف کند.
- **گزارش فعالیت:** ثبت خودکار همه اقدام‌ها (ورود، ورود ناموفق، مسدودسازی، حذف، ساخت مدیر، تغییر رمز) همراه با IP.
- **پروفایل من:** تغییر رمز حساب مدیر جاری.
- امنیت: کوکی نشست جدا (`FITBOTADMINSESS`)، CSRF روی همه فرم‌ها، محدودیت نرخ ورود (۸ تلاش در ۵ دقیقه)، هش bcrypt و پوشه خصوصی نشست در `storage/admin-sessions` خارج از دسترسی وب.

## صفحه ورود و ثبت‌نام مستقل کاربران

علاوه بر پنجره ورود داخل خود برنامه، صفحه مستقل `public/login.php` هم هست:

- تب **ورود** و تب **ساخت حساب** با اعتبارسنجی کامل و پیام‌های فارسی.
- بعد از ورود/ثبت‌نام موفق، مستقیم به برنامه (`index.php`) هدایت می‌شوی.
- همان منطق `Auth` برنامه (هش bcrypt، محدودیت نرخ، CSRF) را استفاده می‌کند؛ ثبت‌نام از این صفحه حساب خالی می‌سازد (انتقال داده مهمان فقط از داخل برنامه انجام می‌شود).

## پلتفرم مدیریت باشگاه (فاز ۱)

از نسخه ۴، هسته‌ی پلتفرم مدیریت مجموعه ورزشی (پروپوزال) به برنامه اضافه شده است؛ معماری ماژولار با مهاجرت خودکار دیتابیس برای MySQL و SQLite:

- **نقش‌ها و دسترسی‌ها (RBAC):** ۱۶ نقش سیستمی (مدیرعامل، مدیر داخلی، مالی، سرمربی، مربی، منابع انسانی، پذیرش، اپراتور CRM، انباردار، مسئول کافه/فروشگاه/آرایشگاه/ماساژ، عضو، عضو افتخاری، مهمان) + ساخت نقش سفارشی. دسترسی هر نقش از صفحه «نقش‌ها و دسترسی‌ها» قابل تنظیم است؛ منوی پنل هر کارمند فقط بخش‌های مجاز او را نشان می‌دهد و اقدامات حساس (مالی، حذف و…) روی سرور کنترل می‌شوند.
- **کارکنان:** ساخت حساب کارمندی با نقش‌های دلخواه؛ نقش‌ها تجمعی هستند و «مدیر کل» از همه محدودیت‌ها عبور می‌کند.
- **شعب (Multi-Branch):** تعریف شعبه با کد یکتا؛ اعضا، پلن‌ها، لیدها و تراکنش‌ها به شعبه متصل می‌شوند.
- **CRM و لیدها:** ثبت لید با منبع جذب (اینستاگرام، تبلیغات، تماس، حضوری، معرفی)، قیف وضعیت (جدید ← تماس ← مشاوره ← عضو/منصرف)، اپراتور پیگیری، ثبت تماس و رویداد در پرونده لید و یادآوری پیگیری.
- **عضویت‌ها:** پلن‌های ماهانه/جلسه‌ای/زمانی/VIP/افتخاری/مربی/ترکیبی/اشتراک اپلیکیشن با قیمت و مدت دلخواه؛ ثبت اشتراک برای عضو با محاسبه خودکار انقضا و جلسات، ثبت مصرف جلسه و لغو. فروش پلن پولی به‌صورت خودکار در بخش مالی ثبت می‌شود.
- **کیف پول اعضا:** شارژ/برداشت با دفتر تراکنش و مانده لحظه‌ای در پرونده عضو.
- **تردد:** ثبت ورود/خروج با روش‌های دستی، QR، کارت، OTP، اثر انگشت و چهره (آماده برای اتصال به گیت در فاز IoT).
- **مالی:** دفتر درآمد/هزینه با دسته‌بندی کامل (عضویت، خدمات، مربی، کافه، فروشگاه، … / حقوق، اجاره، خرید، تجهیزات، …)، سود ماهانه و کل.
- **داشبورد مدیرعامل:** آمار زنده اعضا، اشتراک‌های فعال و در حال انقضا، لیدها، درآمد/هزینه/سود ماه و فعالیت‌های اخیر — همه بر اساس سطح دسترسی کاربر پنل.
- **جداول آماده فازهای بعد:** دفتر کل توکن، نقش‌های اعضا (user_roles) و ستون شعبه در جدول اعضا؛ فروشگاه، کافه، انبار، مسابقات، شبکه اجتماعی، AI Coach و IoT روی همین هسته ساخته می‌شوند.

**مهاجرت دیتابیس:** اگر دیتابیس نسخه قبلی را داشته باشی، در اولین اجرای برنامه همه جداول و ستون‌های جدید خودکار ساخته می‌شوند؛ نیازی به ایمپورت مجدد نیست. برای نصب تمیز، فایل `database/fitbot_mysql.sql` را در یک دیتابیس جدید ایمپورت کن.

## پلتفرم مدیریت باشگاه (فاز ۲) — خدمات، رزرو، فروشگاه و کافه

فاز دوم بر اساس بندهای ۷ (خدمات و رزرو)، ۸ (فروشگاه) و ۲۷ (کافه) پروپوزال اجرا شده و یک **پنل کاربری مستقل برای اعضا** به آن اضافه شده است. معماری همان ماژولار/API-first فاز ۱ است و دیتابیس به **نسخه ۵ (۲۶ جدول)** ارتقا یافته.

### خدمات و رزروها (بند ۷)

- ۱۳ دسته خدمت: بدنسازی، مربی خصوصی، کلاس گروهی، ماساژ، آرایشگاه، کافه، پارکینگ، کمد، فیزیوتراپی، پزشک، استخر، لاغری و سایر.
- هر خدمت دارای قیمت (تومان)، مدت، ظرفیت و وضعیت فعال/غیرفعال؛ ساخت و ویرایش از پنل ادمین.
- عضو از پنل خود زمان دلخواه را رزرو می‌کند (بازه مجاز: یک ساعت قبل تا ۶۰ روز بعد، تقویم شمسی در رابط).
- گردش کار رزرو: `در انتظار تأیید ← تأییدشده ← انجام‌شده / لغوشده`؛ تأیید و ثبت نهایی با پذیرش انجام می‌شود و رزرو انجام‌شده به‌صورت خودکار درآمد (دسته «خدمات») ثبت می‌کند.

### فروشگاه و کافه (بندهای ۸ و ۲۷)

- محصولات دو بخش «فروشگاه» (مکمل، لوازم، پوشاک) و «کافه» (نوشیدنی) با قیمت، موجودی و آستانه کمبود.
- سفارش عضو با دو روش پرداخت: **کیف پول** (کسر فوری و ثبت درآمد) یا **نقدی** (پرداخت در محل، درآمد هنگام تحویل).
- گردش سفارش: `در انتظار ← پرداخت‌شده ← در حال آماده‌سازی ← تحویل‌شده / لغوشده`؛ لغو سفارش، مبلغ را به کیف پول برمی‌گرداند و موجودی را به انبار ضایع نمی‌کند (حرکت «مرجوعی» ثبت می‌شود).
- مدیریت انبار با دفتر حرکت‌ها (خرید/فروش/مرجوعی/ضایعات/اصلاح)؛ فروش از موجودی کم می‌کند و موجودی منفی مسدود است. هشدار کمبود موجودی در فهرست محصولات و داشبورد.

### پنل کاربری اعضا (`panel.php`)

- چهار تب: **خانه** (خلاصه کیف پول، توکن، رزروهای فعال و آخرین سفارش‌ها)، **خدمات** (رزرو نوبت)، **فروشگاه** (خرید محصولات فروشگاه و کافه) و **سفارش‌ها** (سوابق رزرو و سفارش).
- ورود با همان حساب کاربری سایت (جدا از ورود مدیران)؛ همه فرم‌ها با CSRF محافظت می‌شوند.
- طراحی راست‌به‌چپ مستقل با فونت وزیرمتن و تصاویر اختصاصی (`public/assets/images/`).

### تغییرات صفحه اصلی سایت

- در نمای کلی، بخش جدید «باشگاه فیت‌بات؛ بیشتر از یک سالن تمرین» با سه کارت تصویری (خدمات و نوبت، فروشگاه باشگاه، کافه انرژی) و میان‌بر مستقیم به پنل اضافه شد؛ لینک «پنل باشگاه» نیز در منوی کناری در دسترس است.

### داده نمونه (Seed)

- در اولین اجرا روی دیتابیس خالی، داده واقع‌نما ساخته می‌شود: ۶ پلن، ۱۰ خدمت، ۱۴ محصول (تومان)، عضو نمونه با اشتراک فعال، کیف پول، توکن، ۲۰ رکورد تردد، ۳ رزرو، ۲ سفارش، ۴ لید و ۷ سند مالی.
- برای محیط تست/CI این داده غیرفعال می‌شود: `FITBOT_NO_DEMO=1`.
- ورودهای نمونه — عضو: `demo@fitbot.ir` / `Demo@12345` — مدیر: `admin` / `Admin@12345`.

### دسترسی‌های جدید (RBAC)

مجوزهای `services.view/manage` و `store.view/manage` اضافه شد و به نقش‌های مرتبط (پذیرش، مدیر داخلی، سرمربی برای خدمات؛ انباردار، مسئول کافه و فروشگاه برای فروشگاه؛ مالی با دید فروشگاه) به‌صورت پیش‌فرض داده شده‌اند؛ قابل تغییر از صفحه «نقش‌ها و دسترسی‌ها».

### دیتابیس نسخه ۵

جداول جدید: `services`، `reservations`، `products`، `orders`، `order_items`، `inventory_movements` و `platform_meta`. اگر دیتابیس نسخه ۴ را داشته باشی، در اولین اجرا همه جداول و مجوزهای جدید **بدون از دست رفتن داده** ساخته می‌شوند (مهاجرت درجا آزمایش شده است). برای نصب تمیز، فایل `database/fitbot_mysql.sql` (نسخه ۵) را ایمپورت کن؛ داده نمونه در اولین بازدید خودکار ساخته می‌شود.

## امکانات اجراشده

- داشبورد واکنش‌گرا، تم روشن/تاریک، فونت فارسی محلی و ناوبری موبایل.
- ورود، ثبت‌نام، خروج و حذف حساب با تأیید رمز.
- اطلاعات جداگانه هر حساب در MySQL یا SQLite؛ رمزها با `password_hash` ذخیره می‌شوند.
- حالت مهمان مستقل از حساب: داده مهمان در مرورگر باقی می‌ماند و فقط با انتخاب صریح هنگام ثبت‌نام به حساب جدید منتقل می‌شود.
- ذخیره خودکار داده حساب با نشانگر وضعیت؛ داده‌های حساب در localStorage مهمان نوشته نمی‌شوند.
- کنترل تداخل نسخه‌ها: تغییرات قدیمی، داده دستگاه یا تب دیگر را بی‌خبر جایگزین نمی‌کنند؛ انتخاب نسخه از پنجره حساب انجام می‌شود.
- برنامه‌ساز سه‌مرحله‌ای با ۲ تا ۵ روز تمرین، سطح تجربه، زمان و تجهیزات. مرحله مرور برنامه از API واقعی PHP نتیجه می‌گیرد.
- محاسبه‌گر BMR، TDEE و ماکرو با فرمول Mifflin–St Jeor و اعتبارسنجی سمت سرور. پیش‌نمایش‌های فوری رابط نیز منطق متناظر دارند؛ محاسبه‌گر و مرور نهایی برنامه از PHP استفاده می‌کنند.
- کتابخانه ۲۴ حرکت با جستجو، فیلتر، علاقه‌مندی، راهنمای متنی و انیمیشن نمادین قابل توقف.
- جلسه تمرین، ثبت تکمیل حرکات و تایمر استراحت با مکث/ادامه.
- ثبت وزن، نمودار واقعی، تقویم جلسه‌های تکمیل‌شده، ثبت آب و وعده‌های غذایی.
- سهم‌های غذایی تخمینی و پیشنهاد گیاهی؛ مواد و ماکروهای وعده ثبت‌شده با تغییر هدف دوباره‌نویسی نمی‌شوند.
- هماهنگ‌کننده و سه نقش تمرین، تغذیه و ریکاوری؛ راهنمای قانون‌محور داخلی و اتصال اختیاری به مدل زبانی.
- پیشنهاد اقدام در گفتگو؛ ثبت آب و تغییر هدف فقط پس از کلیک تأیید اجرا می‌شوند.
- خروجی برنامه TXT، اندازه‌گیری CSV، پشتیبان JSON و بازیابی پشتیبان.
- فرمان‌های سریع با `Ctrl+K` یا `Cmd+K`، کنترل صفحه‌کلید و پشتیبانی `prefers-reduced-motion`.
- انیمیشن ذرات محدود به ناحیه قابل مشاهده، پارالاکس ملایم، مدار ایجنت‌ها، رسم نمودار، گذار پنجره‌ها و بازخورد تکمیل تمرین.

## اتصال واقعی مدل زبانی

بدون کلید، همه امکانات پایه و راهنمای قانون‌محور داخلی کار می‌کنند. **این راهنمای داخلی یک مدل زبانی نیست.**

۱. فایل `.env.example` را در ریشه پروژه به `.env` کپی کن:

```bash
cp .env.example .env
```

در ویندوز می‌توانی فایل را دستی کپی و تغییرنام بدهی.

۲. فقط در فایل سرور تنظیم کن:

```dotenv
OPENAI_API_KEY=your_server_side_key
OPENAI_MODEL=gpt-4.1-mini
OPENAI_BASE_URL=https://api.openai.com/v1
AI_USER_DAILY_LIMIT=30
AI_GLOBAL_DAILY_LIMIT=100
```

مدل باید از **Chat Completions و tool calling** پشتیبانی کند. نشانی سرویس دیگرِ سازگار را هم می‌توان در `OPENAI_BASE_URL` تنظیم کرد. URL و کلید از مرورگر گرفته نمی‌شوند. اگر مدل از پارامترهای `max_tokens` یا `temperature` پشتیبانی نمی‌کند، payload را در `app/AgentService.php` متناسب با مستندات همان سرویس تغییر بده.

۳. وارد حساب شو. در «تیم ایجنت‌ها ← اتصال هوش مصنوعی»، رضایت ارسال پیام و مشخصات پایه را تأیید و حالت مدل را فعال کن.

- کلید واقعی داخل HTML، JavaScript، پاسخ API یا فایل ZIP نیست.
- درخواست از `public/api.php?action=agent` به `app/AgentService.php` می‌رود و با cURL به سرویس مدل ارسال می‌شود.
- مدل فقط پیشنهاد اقدام برمی‌گرداند؛ نوشتن خودکار در سوابق سلامت مجاز نیست.
- حالت مدل پس از تازه‌سازی صفحه دوباره نیاز به فعال‌سازی دارد.
- هزینه و سیاست نگهداری داده به سرویس انتخابی بستگی دارد. محدودیت داخلی، سقف تعداد درخواست است، نه تضمین سقف هزینه؛ روی حساب ارائه‌دهنده هم محدودیت بودجه قرار بده.
- مسیر cURL و قرارداد tool calling با سرویس آزمایشی محلی تست شده‌اند. کلید سرویس واقعی در این پروژه تنظیم نشده و اتصال زنده با حساب واقعی تست نشده است.

## ذخیره و حریم خصوصی

### مهمان

کلید `fitbot.php.guest.v1` در localStorage فقط اطلاعات مهمان را نگه می‌دارد. اگر مرورگر یا iframe ذخیره‌سازی را محدود کند، نشانگر حالت موقت نمایش داده می‌شود. مشخصات واردشده برای محاسبه نهایی به PHP همین برنامه فرستاده می‌شوند، اما بدون حساب در جدول سوابق کاربران ثبت نمی‌شوند.

### حساب

سوابق و گفتگوها روی سرور همین برنامه ذخیره می‌شوند. نشانگر بالای صفحه وضعیت «ذخیره‌شده»، «در انتظار»، «خطا» یا «تداخل نسخه» را مشخص می‌کند. پیش از خروج یا بستن صفحه، ذخیره‌شدن را بررسی کن. خطای شبکه یا تداخل، به‌عنوان ذخیره موفق نمایش داده نمی‌شود. در قطع اتصال، اطلاعات جدید در حافظه همان صفحه می‌مانند؛ پشتیبان بگیر.

- خروج، داده حساب را از رابط و سند جاری پاک می‌کند و داده مستقل مهمان را دوباره بارگیری می‌کند.
- «پاک‌کردن داده‌های ورزشی» حساب را نگه می‌دارد ولی برنامه و سوابق آن را پاک می‌کند.
- «حذف حساب» در پنجره حساب، با تأیید رمز، رکورد کاربر و سوابق وابسته را حذف می‌کند.
- پشتیبان‌های دانلودشده یا پشتیبان سرور جداگانه‌اند و خودکار از دستگاه‌های دیگر پاک نمی‌شوند.
- پایگاه داده (SQLite یا MySQL) به‌صورت پیش‌فرض رمزنگاری در حالت سکون ندارد. فایل‌ها، پوشه storage، فایل `.env` و نسخه‌های پشتیبان باید در دسترس عمومی نباشند. رمز کاربران دیتابیس را در `.env` فقط روی سرور نگه دار. برای اطلاعات حساس و انتشار واقعی، مدیریت دسترسی، رمزنگاری مناسب، سیاست نگهداری داده و ممیزی لازم است.
- ظرفیت نگهداری فعلی: حداکثر ۱۰۰۰ ثبت وزن، ۱۰۰۰ جلسه، ۳۶۵ روز داده آب/غذا، ۴۰ پیام برای هر نقش و ۴۰ رویداد. حجم snapshot محدود است؛ خروجی‌های دوره‌ای نگه دار.

## دیتابیس و ساختار

```text
fitbot-php/
├── public/
│   ├── index.php              # ساخت سند و داده اولیه مجاز همان حساب
│   ├── login.php              # صفحه مستقل ورود/ثبت‌نام کاربران
│   ├── api.php                # API با session و CSRF
│   ├── admin/                 # پنل مدیریت (لاگین، داشبورد، کاربران، مدیران، گزارش، پروفایل)
│   └── assets/                # CSS، JavaScript، عکس و فونت محلی
├── app/
│   ├── bootstrap.php         # راه‌اندازی و autoload بدون Composer
│   ├── Config.php            # متغیر محیطی و .env
│   ├── Auth.php              # حساب کاربر، نشست، هش رمز، مسدودسازی
│   ├── AdminAuth.php         # نشست جداگانه مدیران، CSRF، ثبت فعالیت
│   ├── Database.php          # PDO (MySQL/SQLite)، schema، نسخه داده، rate limit
│   ├── StateValidator.php    # اعتبارسنجی و حذف فیلدهای ناشناخته
│   ├── FitnessService.php    # محاسبه انرژی و تولید برنامه در PHP
│   ├── AgentService.php      # مدل زبانی و پیشنهاد ابزار با cURL
│   ├── Http.php              # پاسخ، ورودی JSON و CSRF
│   ├── ApiException.php
│   └── data/                 # کاتالوگ حرکت، نقش‌ها و داده‌های نمونه
├── database/
│   └── fitbot_mysql.sql      # فایل ایمپورت MySQL (جداول + مدیر پیش‌فرض)

├── router.php                # فقط برای سرور توسعه PHP
├── .env.example
├── API.md
└── README.fa.md
```

جدول‌ها:

- `users`: نام، ایمیل، هش رمز و زمان ایجاد.
- `user_states`: یک snapshot JSON اعتبارسنجی‌شده برای هر کاربر، همراه شماره نسخه و زمان ذخیره. این نسخه برای سادگی انتقال و backup، به‌جای جدول مجزا برای هر نوع حرکت/وعده از snapshot استفاده می‌کند.
- `rate_limits`: شمارنده محدودیت درخواست؛ کلیدها هش شده‌اند.

JSON پشتیبان هنوز `version: 2` دارد تا با ساختار داده نسخه قبلی سازگار باشد؛ نسخه نرم‌افزار PHP برابر ۳.۰ است.

## اجرای تست

از ریشه پروژه:

```bash
php tests/run.php
```

تست، دیتابیس موقت مستقل می‌سازد و پس از پایان پاک می‌کند؛ دیتابیس واقعی پروژه را تغییر نمی‌دهد. ۲۸۸ ترکیب پارامتر برنامه‌ساز، فرمول‌ها، اعتبارسنجی، round-trip دیتابیس، رد نسخه قدیمی، محدودیت ابزارهای مدل و حذف وابسته داده را پوشش می‌دهد. اجرای برنامه و همین تست به Node نیاز ندارد.

علاوه بر تست همراه، در زمان ساخت ۶۸ بررسی مرورگری/HTTP و ۱۳ بررسی اتصال مدل با mock اجرا شده‌اند؛ جزئیات در `TEST_REPORT.fa.md` است.

## انتشار و محدودیت‌های نسخه

- سرور `php -S` فقط برای توسعه است. برای انتشار از PHP-FPM/Apache و HTTPS استفاده کن.
- فقط `public/` در معرض وب باشد؛ `.env`، دیتابیس، session و گزارش‌ها هرگز داخل پوشه عمومی قرار نگیرند.
- `APP_ENV=production` را تنظیم کن. عملیات ورود/ثبت‌نام در این حالت بدون شناسایی HTTPS رد می‌شود.
- پشت پروکسی مورد اعتماد، `TRUST_PROXY=true` قرار بده. این گزینه را وقتی سرور از اینترنت مستقیم و بدون پروکسی قابل دسترسی است، کورکورانه فعال نکن.
- در حالت trusted proxy، هدر `X-Forwarded-Host` هم بررسی می‌شود. اگر مبدأ هنوز با تنظیم پروکسی هماهنگ نیست، `APP_ORIGIN` را برابر مبدأ دقیق قابل مشاهده برای مرورگر، بدون اسلش انتهایی تنظیم کن.
- نشست‌ها پس از دو ساعت عدم فعالیت حساب منقضی می‌شوند؛ کوکی HttpOnly و در HTTPS به‌صورت Secure است.
- برای iframe روی HTTPS می‌توان از `SESSION_SAMESITE=None` و `SESSION_PARTITIONED=true` استفاده کرد (مرورگرهای دارای CHIPS). اگر کوکی همچنان محدود است، از تب مستقل استفاده کن. پیش‌فرض معمول، `Lax` است.
- CSRF، SQL پارامتری، CSP با nonce، محدودیت اندازه درخواست و rate limit اضافه شده‌اند؛ این‌ها به معنای «امنیت تضمین‌شده» یا آماده‌بودن برای هر محیط تولید نیستند.
- در این نسخه ایمیل تأیید نمی‌شود، بازیابی رمز با ایمیل و MFA وجود ندارد. پیش از انتشار عمومی، این امکانات، پایش و پشتیبان‌گیری مدیریتی را اضافه کن.
- برای پشت پروکسی بزرگ، rate limit پیش‌فرض از IP اتصال استفاده می‌کند، نه X-Forwarded-For دلخواه کاربر؛ ممکن است چند کاربر محدودیت مشترک داشته باشند. تنظیم trusted proxy را متناسب با زیرساخت بررسی کن.
